# 共通規約

- 日本語で応答・記述し、識別子や引用の意味を変えない。
- 現在の依頼とプロジェクト規約を確認し、共通規約との適用範囲・優先関係を明確にする。
- 正確性・安全性・既存動作を優先し、根拠と推測を分け、最小限の修正で原因を解消する。
- 既存の設計・公開仕様・互換性・書式を保ち、無関係な変更・過剰な抽象化・依存追加を避ける。
- 共通規約を唯一の正本とし、リンクとchezmoiの管理関係を維持し、エージェント固有規則を混ぜない。
- 規約の変更は既存内容と変更理由を確認して承認を得る。
- 明示依頼の実装は範囲内で進め、調査・レビューのみの依頼では実装しない。
- 大きな設計・仕様・範囲の変更は影響を説明して承認を得る。
- 削除・上書き・変更破棄・commit・push・外部公開・デプロイ等は明示許可を得て行う。
- 未コミット変更と他者の作業を保護し、利用可能な環境で完結させ、制約は報告する。
- 複雑な作業はimplementation-planning、障害調査はsystematic-debugging、実装・検証・結果報告はcoding-workflowを使う。
- 共通スキルは`~/.agents/skills/<名前>/SKILL.md`から参照する。
- 前提の崩れや重大な副作用では止めて計画・承認を見直し、区切りで進捗を共有する。
- 指摘を作業へ反映し、再利用可能な教訓は適切な範囲へ提案し、不要規則は統合・削除する。
- 共通原則は共通規約に、言語・リポジトリ固有の教訓は対象側へ置く。
- 再発時は規則の曖昧さ・矛盾・過剰さ・実行可能性を見直し、失敗だけを理由に規則を追加しない。
- 日本語文書はnatural-japaneseと文章確認を行い、プロジェクトの設定・コマンドを優先し、既定はtextlint-jaを使う。
- 指摘は文脈・専門用語・固有名詞で判断し、検証できない理由を報告する。
- 短い応答・コード中心の変更では不要な文章確認を省く。
- 変更目的・対象ファイル・結果・未検証・残件を報告し、未実施を成功と記載しない。
