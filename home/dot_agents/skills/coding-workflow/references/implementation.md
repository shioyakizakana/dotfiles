# 編集とコメント

- 既存の設計・命名・公開インターフェース・スタイルに合わせ、要求を満たす最小の変更を選ぶ。
- 新しい設計や依存を導入する前に既存の仕組みで足りるか確認する。
- 不明な仕様を補完せず、既存コードからの推測と未確定事項を分ける。
- 症状だけを隠さず、ログ・失敗テスト・再現手順・コードの動作から原因を確認する。
- バグ修正の依頼は承認範囲内で調査・修正・検証まで進める。
- 関連のない整形・命名変更・ファイル移動・依存更新を混ぜない。
- 編集方法は差分の大きさと安全性で選び、多数の細切れ編集より範囲単位の編集を優先する。
- 全体の書き換えは明らかに安全・効率的な場合に限定し、既存内容・書式・改行・文字コードの保持を確認する。
- コードは処理の仕組みが分かる名前と単純な構造で書く。
- コメントは逐語説明を避け、判断理由・制約・採用しなかった方法を必要に応じて記す。
- コメントと文書は原則日本語とし、識別子・固有名詞とプロジェクト固有規約を尊重する。
