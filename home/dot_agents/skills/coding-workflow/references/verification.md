# 検証と報告

- 計画には変更に応じた再現・単体・統合テスト、静的解析、ビルド、ログ確認を含める。
- バグ修正時は可能なら再現テストを追加し、修正前後を同じ条件で比較する。
- テストでは現在期待する動作を表し、実装内部・変更前との差分・削除済み機能の不在だけに依存しない。
- 関連するCI失敗は承認範囲で修正し、無関係な失敗は根拠を示して報告する。
- 成功させるためにテストを弱めたり検証を削除したりしない。
- 完了時は変更目的・対象ファイル・主な変更・実行結果・未実施・理由・残るリスクを報告する。
- 検証できない場合は成功を断言せず、理由と代替確認方法を示す。
- エラーの説明では確認した事実と推測を区別し、未実行を実施済みと記載しない。
- 日本語文書はnatural-japaneseを優先し、既存のプロジェクト設定に従って文章を確認する。
- リンターの指摘は文脈・専門用語・引用を考慮して判断し、実行不能理由を報告する。
