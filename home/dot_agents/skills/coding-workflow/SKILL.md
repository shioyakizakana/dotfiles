# Coding Workflow

- 変更前にGit状態・関連コード・テスト・設定・文書を確認する。
- 実装・編集では[編集とコメント](references/implementation.md)を読む。
- 検証・完了報告では[検証と報告](references/verification.md)を読む。
- 複雑な作業はimplementation-planning、障害の原因調査はsystematic-debuggingの手順を使う。
- ワークアラウンドは理由・制約・解消条件を示し、恒久解決として扱わない。
- 許可されたコミットでは目的と理由を簡潔なメッセージにする。
