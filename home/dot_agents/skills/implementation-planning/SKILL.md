# Implementation Planning

## 手順

1. ユーザーの目的と完了条件を整理する。
2. 既存の構成、仕様、制約を確認する。
3. 必要な仕様と不明点を明確化する。
4. 最も単純で実現可能な案を検討する。
5. 必要に応じて代替案とトレードオフを比較する。
6. 実装手順と各段階の検証方法を定義する。
7. 想定されるリスクとロールバック方法を検討する。
8. 必要な承認を得てから実装へ進む。

## 計画の内容

- 目的と対象範囲
- 仕様と受け入れ条件
- 既存コードへの影響
- 実装ステップ
- テスト・検証方法
- リスクと未決事項

## 制約

- 単純な作業に詳細な計画書を要求しない。
- 計画を作るためだけに新規ファイルを増やさない。
- 既存の仕様書や計画がある場合は再利用する。
- 想定から外れた場合は計画を見直す。
- 既存の計画機能で十分な場合は重複利用しない。
