# Systematic Debugging

## 目的

推測に基づく場当たり的な修正を避け、
観測可能な証拠を用いて根本原因を解決する。

## 手順

### 1. 現象の確認

1. ユーザーの報告内容と期待する動作を整理する。
2. 関連するコード、テスト、設定、ログを確認する。
3. 再現条件と影響範囲を特定する。
4. 再現できない場合は不足情報を明示する。

### 2. 原因の調査

1. ログ、例外、失敗したテストを証拠として収集する。
2. 原因の仮説を立て、検証可能な形に整理する。
3. 仮説を一つずつ検証する。
4. 症状と根本原因を区別する。
5. 根拠が不十分な段階では修正を確定しない。

### 3. 修正方針の決定

1. 原因を取り除く最も単純な方法を優先する。
2. 既存の設計や公開インターフェースを尊重する。
3. 変更範囲と副作用を確認する。
4. 一時的な回避策である場合は、その限界を明示する。
5. 設計変更や作業範囲の拡大には必要な承認を得る。

### 4. 実装

1. 可能であれば修正前に不具合を再現するテストを作成する。
2. 根本原因を対象に必要最小限の変更を行う。
3. 無関係なコードの整理や機能追加を混在させない。

### 5. 検証

1. 不具合の再現テストを実行する。
2. 関連する既存テストを実行する。
3. 境界値と異常系を確認する。
4. 差分を確認して意図しない変更がないことを確かめる。
5. 実行できなかった検証は未実施として報告する。

## 完了報告

以下の内容を簡潔に報告する。

- 確認した現象
- 特定した根本原因とその根拠
- 実施した修正
- 検証方法と結果
- 未解決事項や残存リスク

原因が特定できなかった場合、
推測を確定事項として報告しない。
