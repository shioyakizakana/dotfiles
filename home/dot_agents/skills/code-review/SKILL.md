# Code Review

## 手順

1. レビュー対象と期待する動作を確認する。
2. 関連するコード、呼び出し元、テストを調査する。
3. 再現可能な不具合や具体的なリスクを優先して探す。
4. 各指摘に根拠と影響範囲を付ける。
5. 最小限の修正案を提示する。
6. 指摘事項と任意の改善提案を区別する。

## 出力

指摘事項を重大度の高い順に報告する。

各指摘には以下を含める。

- 重大度（高・中・低）
- 該当ファイルと行番号
- 問題点
- 根拠と影響
- 推奨する修正方針

問題が確認できない場合はその旨を明示する。
実行できなかったテストや未確認事項も報告する。

## 制約

- 原則としてレビュー中にコードを変更しない。
- 推測だけで不具合が存在すると断定しない。
- 単純な処理に不必要な抽象化を提案しない。
