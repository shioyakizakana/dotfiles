# dotfilesリポジトリの現状調査と改善管理

初期構築と通常運用の分離、暗号化保存、既存鍵の保護には明確な設計がある。一方、PATの不要な継承と、新規環境での構築を妨げるコードが見つかった。秘密情報の保持範囲と初期構築の失敗経路から改善する。

## この文書の使い方

- 調査日：2026-11-06。調査対象は当日の作業ツリー。
- IDは継続利用し、修正後も削除・再採番しない。
- 状況は「未着手」「対応中」「修正済み・未適用」「完了」「保留」で記録する。「完了」は項目ごとの受け入れ条件を満たした状態とする。
- 各項目の根拠、判断、検証結果、残件を更新する。行番号は初回調査時点の目安であり、変更後は該当処理も照合する。
- 実環境への適用・認証・外部通信を行う場合は、別途承認を得る。コード修正と適用の状態を区別する。
- 実行していない動作を再現済みと記録しない。秘密情報は証跡に含めない。

## C. 改善項目の詳細

### DF-01：常駐プロセスへのPAT継承

- 根拠：`home/dot_local/bin/executable_proton-pass.tmpl:72-83`でログイン用PATをexportしてヘルパーを起動。`home/dot_local/bin/private_executable_proton-pass-key-cache.py.tmpl:190-199`の`Popen`が環境を無条件に継承する。
- 判断・影響：初回調査では静的に確認した経路。今回の回帰テストで、修正前はダミーPATが常駐プロセスへ継承されることを確認した。env方式でキャッシュがない状態からログインすると、CLI終了後も常駐プロセスにPATが残る可能性がある。実PATは使用していない。
- 対応方針：常駐用環境からPATとCLI暗号化鍵の環境変数を除外する。ログイン用CLIへのPAT受け渡しと、PATHなど必要な設定は維持する。全面的な許可リスト方式は互換性への影響が大きいため、最小修正では採用しない。
- 注意・検証：ダミー値とプロセス起動のモックで、常駐側への秘密変数の不在、呼び出し側環境の保持、CLI側への必要値の引き渡しを確認する。実際の復号・認証は不要。
- 残件：鍵未投入の常駐プロセスには終了期限がない（同ファイル125-127行）。起動待ち期限は別途検討し、今回の継承防止とは分ける。
- 対応状況：修正済み・未適用。`os.environ.copy()`から2つの秘密変数を除いた環境を常駐用`Popen`へ明示した。呼び出し側の環境とログイン用CLIへの受け渡しは維持する。
- 受け入れ条件と結果：秘密変数を常駐側へ渡さないこと、必要な実行設定と呼び出し側環境を維持すること、ログイン用CLIへPATとキャッシュ鍵を渡すこと、既存キャッシュを再利用することをモックで確認。3テスト成功。実機適用・認証・既に稼働中のキャッシュの変更は未実施。
- 回帰テスト：`tests/test_proton_pass_key_cache.py`。実行コマンドは`python3 -B -m unittest discover -s tests -p test_proton_pass_key_cache.py -v`。復号、ソケット通信、プロセス起動、CLI実行をモックに置き換え、ダミー値のみ使う。
